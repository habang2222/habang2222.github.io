# 실습

![image.png](/image/edr/스크린샷 2026-05-19 205207.png)

1. Get-Service "Elastic Agent”
    
    이 명령어는 Elastic Agent 가 실행 중인지 확인
    
2. Get-Service "ElasticEndpoint”
    
    이 명령어는 EDR 엔드보인트 보호 모듈이 실행중인지 확인
    

결과가 위 처럼 running 이면 둘다 정상 작동중

1. & "C:\Program Files\Elastic\Agent\elastic-agent.exe" status
    
    windows 서비스가 켜져 있는지만 보는 게 아니라, Elastic Agent 내부 구성 요소 상태를 확인 하는 명령어
    

EDR 탐지 실습을 진행하기 전, PowerShell 관리자 권한에서 Get-Service 명령어를 이용해 Elastic Agent와 ElasticEndpoint 서비스의 실행 상태를 확인하였습니다.
Elastic Agent는 Fleet와 통신하며 정책을 적용하고 이벤트를 전송하는 역할을 하며, ElasticEndpoint는 Elastic Defend의 엔드포인트 탐지 기능을 담당한다. 
두 서비스가 모두 Running 상태로 표시되어 EDR 탐지 실습을 수행할 수 있는 기본 환경이 정상적으로 구성되었음을 확인하였다.

이를 통해 Elastic Security가 EICAR 테스트 파일을 악성코드로 탐지하고 차단했음을 확인했습니다.

위 명령어를 실행하면 elasticEndpoint 가 이벤트를 수집하면 kibana에서 확인 할 수 있습니다

[process.name](http://process.name/) : "powershell.exe" : 파워쉘 실행 이벤트를 찾는 명령어

![image.png](/image/edr/스크린샷 2026-05-19 205647.png)

data view ( logs-endpoint.events.* ) 는 Elastic Defend 가 수집한 보안 이벤트 로그를 보는 데이터 뷰

프로세스 실행, 파일 생성, 파일 삭제, 네트워크 연결, DLL 로드, 보안 탐지 관련 이벤트 등이 포함되어 있습니다


시간대별 이벤트 개수

Available 은 로그에서 사용할 수 있는필드 들

| 필드 | 의미 |
| --- | --- |
| `@timestamp` | 이벤트 발생 시간 |
| `agent.id` | 로그를 보낸 Agent ID |
| `agent.version` | Elastic Agent 버전 |
| `data_stream.dataset` | 어떤 종류의 로그인지 |
| `destination.address` | 네트워크 목적지 주소 |
| `dll.*` | 로드된 DLL 정보 |
| `device.*` | 장치 정보 |
| `process.name` | 실행된 프로세스 이름 |
| `process.executable` | 실행 파일 경로 |
| `process.command_line` | 실제 실행된 명령어 |
| `file.name` | 생성/수정/삭제된 파일 이름 |
| `file.path` | 파일 전체 경로 |
| `event.action` | 이벤트 종류 |
| `event.category` | 이벤트 분류 |
| `host.name` | 이벤트가 발생한 컴퓨터 이름 |
| `user.name` | 실행한 사용자 이름 |
| `@timestamp` | 이벤트 발생 시간 |

[process.name](http://process.name/) powershell.exe event.action file_creation [file.name](http://file.name/) eicar.com.txt event.category file
해석 : powershell.exe 프로세스가 eicar.com.txt 파일 생성 이벤트를 발생 시킴

Kibana Discover에서 logs-endpoint.events.* 데이터 뷰를 선택한 뒤 [process.name](http://process.name/):"powershell.exe" 조건으로 검색했습니다
검색 결과 PowerShell 관련 이벤트가 조회되었으며, 로그에서 process.name이 powershell.exe로 표시되는 것을 확인하였습니다.
또한 EICAR 테스트 파일 생성과 관련된 file_creation 이벤트가 기록되어 있어, PowerShell 명령을 통한 파일 생성 행위가 Elastic Endpoint 로그에 수집되었음을 확인했습니다.

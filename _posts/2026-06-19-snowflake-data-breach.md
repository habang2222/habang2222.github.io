# Snowflake 관련 데이터 유출 사고

[노션 원본 보기](https://app.notion.com/p/3840e129ee9b80e79f4afa3ad182fe9b?pvs=1)

### 1. 기업 개요

Snowflake는 클라우드 기반 데이터 플랫폼 기업이다. 기업이 여러 시스템에서 수집한 데이터를 저장, 처리, 분석할 수 있도록 데이터 웨어하우스와 데이터 분석 환경을 제공한다. 고객사는 Snowflake를 이용해 고객 정보, 거래 기록, 통화 기록, 로그 데이터, 분석용 데이터를 저장하고 활용한다.

즉 Snowflake는 데이터를 직접 생산하는 기업이라기보다, 여러 기업이 자신들의 데이터를 저장하고 분석할 수 있도록 클라우드 데이터 플랫폼을 제공하는 회사이다.

### 2. 주요 취약점 및 사고 원인

이 사고의 핵심은 Snowflake 본사 시스템이 직접 뚫린 것이 아니라, 여러 고객사의 Snowflake 계정이 탈취되어 고객 환경에 무단 접근이 발생했다는 점이다. 공격자는 인포스틸러 악성코드 등을 통해 이미 유출된 계정 정보를 확보했고, MFA가 적용되지 않은 고객사 계정으로 Snowflake 환경에 로그인했다.

가장 큰 문제는 MFA가 적용되지 않은 계정이 많았다는 점이다. 클라우드 데이터베이스는 한 번 로그인에 성공하면 대량의 데이터를 빠르게 조회하고 외부로 빼낼 수 있기 때문에 계정 보안이 매우 중요하다.

또한 일부 고객 환경에서는 계정 권한이 과도하게 부여되어 있었을 가능성도 있다. 계정 하나가 탈취되었을 때 너무 많은 데이터에 접근할 수 있으면, 공격자는 짧은 시간 안에 대량의 정보를 유출할 수 있다.

### 3. 공격 전개 과정

공격자는 직원이나 협력사의 PC가 인포스틸러 악성코드에 감염되면서 유출된 계정 정보를 활용했다. 브라우저나 개발 도구에 저장된 Snowflake 계정 정보가 탈취되었고, 공격자는 이 정보를 이용해 고객사의 Snowflake 환경에 로그인했다.

MFA가 설정되어 있지 않은 계정은 아이디와 비밀번호만으로 접속할 수 있었기 때문에 공격이 쉬웠다. 로그인 후 공격자는 데이터베이스 안의 고객 정보, 거래 정보, 통화 기록, 티켓 정보 등 민감한 데이터를 대량으로 조회하고 외부로 유출했다. 이후 유출한 데이터를 판매하거나 공개하겠다고 협박했다.

공격 흐름은 다음과 같이 정리할 수 있다.

직원 또는 협력사 PC가 인포스틸러에 감염
→ 브라우저나 도구에 저장된 Snowflake 계정 정보 탈취
→ MFA 없는 Snowflake 고객 환경에 로그인
→ 데이터베이스 접근
→ 대량 데이터 조회 및 외부 유출
→ 유출 데이터 판매 또는 협박

### 4. 대응 및 방어 방안

Snowflake 사고를 방어하기 위해 가장 중요한 조치는 모든 계정에 MFA를 적용하는 것이다. 특히 관리자 계정, 서비스 계정, 외부 협력사 계정은 일반 계정보다 더 강하게 보호해야 한다. 비밀번호만으로 접속 가능한 계정이 남아 있으면, 인포스틸러로 계정 정보가 유출되는 순간 바로 침해로 이어질 수 있다.

또한 계정별 접근 권한을 최소화해야 한다. 업무에 필요한 데이터만 접근할 수 있도록 권한을 나누고, 대량 조회나 대량 다운로드가 발생하면 즉시 탐지해야 한다.

주요 방어 대책은 다음과 같다.

- 모든 Snowflake 계정에 MFA 적용
- 관리자 계정과 일반 계정 분리
- 서비스 계정 권한 최소화
- 오래된 계정과 미사용 계정 제거
- 비밀번호 브라우저 저장 금지
- 인포스틸러 감염 탐지
- 로그인 위치, 기기, 시간대 이상 징후 탐지
- 대량 데이터 조회 및 외부 전송 탐지
- 데이터베이스 접근 로그 정기 점검
- 중요 데이터 암호화와 마스킹 적용
- 협력사 계정에도 동일한 보안 정책 적용

이 사고는 클라우드 플랫폼 자체가 안전하더라도 고객사의 계정 관리가 허술하면 대규모 데이터 유출이 발생할 수 있다는 점을 보여준다.

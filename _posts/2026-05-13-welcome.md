# git

---
## git 이란 :

코드나 파일의 변경을 기록하고 관리하는 도구.
사용자가 변경한 파일을 저장하고(커밋) 불러올수(pull) 있음

## 1. commit

git commit :

현재 진행상황을 저장할때 사용함

## 2. branch , checkout

git branch [브랜치 이름] :

기존 코드에 영향을 주지 않고 작업을 이어갈때
git checkout [브랜치 이름] :

현재 작업을 이러갈 브런치 선택

## 3. merge

git merge [합칠 브런치]

브런치 끼리 합침

## 4. rebase

git rebase [기준이 될 브랜치]

브런치 하나를 다른 하나의 하위 브런치로 설정하는 명령어

## 5. HEAD

HEAD :  현재 사용자가 보고있는 위치

헤드를 설정하는 방법 : 2번에서 사용했던 checkout
bugFix 에 있던 헤드가 분리되었다 이 상태 에선 커밋을 해도 bugFix 와 함께 이도 하지 않고 HEAD만 이동한다

## 6. ^ , ^^ , ~num

이전에 작업했던 작업물로 이동하는 명령어
HEAD만 옮길수 있는것이 아니라 각각의 브런치도 옮길수 있다 브런치를 옮길때는 -f를 사용한다

git branch -f (옮길 브런치) (기준이 될거)
git branch -f bugFix main~3
git branch -f main c6
git checkout c1

## 7. reset,revert

reset : 그 전 상태로 되돌린다
git reset [돌아갈 위치]

revert : 기존 커밋을 삭제 하지 않고 그 커밋의 변경 내용을 반대로 적용하는 새 커밋을 만드는 명령어

## 8. cherry-pick

git cherry-pick <Commit1> <Commit2> <...>

HEAD아래에 있는 커밋들에 복사본을 만드는 명령어
git cherry-pick c3 c4 c7

## 9. 인터렉티브

git rebase -i HEAD~4 : 해드위에 4개중 선택한것을 복사해서 새로운 브랜치로 만든다(위치 이동 가능
git rebase -i main~4

## 10. 하나의 커밋만
정답
git checkout main
git cherry-pick bugFIx

*오류 찾음 목표처럼 버그픽스를 옮기지 않았는데 정답 처리됨

+git branch -f bugFIx c’

## 11. —amend

—amend : 가장 최근 커밋을 수정하는 옵션
git commit --amend

## 12. tag

tag : 특정 커밋에 이름을 붙임

버전 표기할때 사용함

## 13. describe

'git describe <ee>'

'<ee>'에서 가장 가까운 태그가 어디 위치해 있는지 알려주는 명령어
v1이 2칸 범위에 현재 커밋의 Git 커밋 ID, 여기서는 C6

## 14. rebase 여러개

이렇게 길게 안하고 더 짧게 하는 방법은
git rebase '[기준커밋/브랜치] [옮길브랜치/커밋]'

이런식으로 하면 됨

## 15. ^,~

git branch bughWork main~^2~

버그워크 브런치를 한칸위 두번째무보 한칸위에 만든다

## 16. 확인문제
`원격 저장소는 사용자의 컴퓨터가 아니라 인터넷이나 서버에 있는 깃 저장소`

## 17. clone

git clone : 원격 저장소의 복사본을 로컬에 생성

## 18. origin,o/

origin : 주원격 브랜치 앞에 붙음

## 19. fetch

fetch : 원격 저장소에서 데이터를 가져오는 명령어
git fetch

## 20. pull

pull : 원격 저장소의 변경사항을 사용자 로컬 저장소로 가져와서 합치는 명령어

git fetch; git merge o/main==git pull

## 21. fakeTeamwork

다른 사람이 원격 저장소에 커밋을 올린 상황을 가짜로 만든다
pull, fetch, push같은 원격 저장소 명령어 연습을 위해 다른 사람이 올린 새 커밋이 있어야 하는데 연습할때는 없으니 이 명령어를 사용하는것임

## 23. push

사용자가 한 작업을 원격 저장소에 업로드 하는 명령어

## 24.  —rebase
사용자의 작업물이 진도를 따라가지 못한경우 원격 저장소에 공유 하기전 최신 상태를 강제로 합치는 방법
다른 방법은 새로 브랜치를 만들고 그 브랜치르 업로드 합니다

위 명령어를 정리한것이 —rebase

git pull; git push

= 원격 작업과 내 작업을 합쳐서 올림
git pull --rebase; git push

= 원격 작업 뒤에 내 작업을 다시 붙인 다음 올림

## 25. request

규모가 큰 작업물은 메인 브랜치는 잠겨있기때문에 변경사항을 저장하려면 pull requset

## 26. feature 브랜치 병합하기

이 방법으로 브랜치를 병합하면 최종 본만 로컬에 푸쉬 할 수 있다

## 27. merge 사용

이 방법은 모든 브런치를 다 로컬에 푸쉬 할 수 있다

## 28. 원격 추적
git push 에서도 적용 할 수 있습니다

## 29. push 인자
예를 들어 git push origin main을 해석해보면
내 저장소에 있는 main이라는 이름의 브랜치로 가서 모든 커밋들을 수집하고 origin의 main 브랜치로가서 이 브랜치에 부족한 커밋을 채워 넣는다라는 뜻입니다

## 30. push '<place>' 인자세부

source 와 destination을 모두 지정 하기 위해서는 git push origin '<source>:<destination>' 이런식으로 두개 사이 : 이걸 넣으면 됩니다

만약에 브랜치가 없으면 만들기도 합니다

## 30. git fetch 인자

push 랑 비슷하게
git fetch origin foo라고 하면 원격 저장소의 foo 브랜치로 가서 현재 로컬에 없는 커밋을 가져와 로컬의 o/foo 브랜치 아래에 추가합니다

:도 똑같습니다

## 31. source 오류

git에서는 source 인자를 두가지 방법으로 사용합니다 이 두가지 오용은 git push 와 git fetch에 source에 없을음 지정 할 수 있기때문에 나타납니다 없음을 지정하는 방법은 인자로 아무것도 안 쓰면 됩니다
 예시)
이렇게 하면 foo브랜치를 없앨수 있습니다
fetch로 만들수도 있습니다

## 32. git pull 의 인자

git pull origin foo == git fetch origin foo; git merge o/foo

git pull origin bar:bugfix == git fetch origin bar:bugfix; git merge bugfix

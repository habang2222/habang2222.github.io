# PYLINGUAL 논문 리뷰


## 1. 논문 개요

이 논문은 Python 바이트코드 파일인 `.pyc`를 다시 사람이 읽을 수 있는 Python 소스 코드로 복원하는 디컴파일러 PYLINGUAL을 제안한다. Python은 버전이 올라갈 때마다 opcode, 예외 처리 방식, 바이트코드 생성 방식이 자주 바뀌기 때문에 기존 디컴파일러를 유지보수하기 어렵다. 특히 Python 3.11 이후 `zero-cost exception`과 같은 변화가 도입되면서 기존 규칙 기반 디컴파일러의 한계가 더 뚜렷해졌다.

논문의 핵심 문제의식은 Python의 빠른 언어 변화에 안정적으로 대응할 수 있는 디컴파일러를 어떻게 만들 것인가이다. 기존 도구들은 버전별 문법 규칙과 사람이 작성한 패턴에 많이 의존했기 때문에 새로운 Python 버전이 나올 때마다 많은 수정이 필요했다. 이에 비해 PYLINGUAL은 데이터 기반 NLP 모델과 기계적인 제어 흐름 분석을 결합하여, 변화하는 바이트코드 구조에 더 유연하게 대응하려는 접근을 취한다.

## 2. 연구 배경과 문제점

Python 디컴파일은 단순히 바이트코드를 다시 문장으로 바꾸는 작업이 아니다. Python 바이트코드는 함수, 클래스, 리스트 컴프리헨션 등으로 나뉘는 코드 객체 구조를 가지며, 각 코드 객체는 명령어, 상수 테이블, 변수 이름 테이블, 디버깅 메타데이터 등을 포함한다. 이러한 구조는 디컴파일 과정에서 함수 경계를 명확히 알 수 있다는 장점이 있다.

하지만 Python은 바이트코드 명세가 안정적이지 않다는 문제가 있다. Java 바이트코드가 오랜 기간 비교적 안정적으로 유지된 것과 달리, Python은 minor 버전이 바뀔 때마다 opcode가 추가, 삭제, 수정되는 경우가 많다. 또한 opcode 자체뿐 아니라 컴파일러가 코드를 바이트코드로 바꾸는 방식도 자주 변한다. 이 때문에 기존 Python 디컴파일러들은 최신 Python 버전을 빠르게 따라가지 못했다.

특히 Python 3.11에서 도입된 예외 처리 구조 변화는 중요한 전환점이다. 기존에는 예외 처리를 위해 block stack을 사용했지만, Python 3.11부터는 exception table을 사용하는 방식으로 바뀌었다. 이 변화는 디컴파일러가 제어 흐름을 복원하는 방식에도 직접적인 영향을 준다. 따라서 Python 디컴파일러는 단순한 문장 번역뿐 아니라 버전별 제어 흐름 차이까지 처리해야 한다.

## 3. PYLINGUAL의 핵심 아이디어

PYLINGUAL은 기존 디컴파일러처럼 모든 버전별 규칙을 사람이 직접 작성하는 대신, NLP 모델을 활용해 바이트코드 문장을 Python 소스 코드 문장으로 번역한다. 동시에 제어 흐름 복원과 결과 검증은 기계적인 분석 방식으로 처리한다.

전체 과정은 크게 다음과 같이 구성된다.

첫째, 바이트코드와 소스 코드에 대해 정규화를 수행한다. 변수 이름이나 상수값을 마스크 형태로 바꾸어 모델이 처리해야 할 입력 복잡도를 줄인다. 원래 값은 따로 저장해 두었다가 마지막에 다시 복원한다.

둘째, 바이트코드를 문장 단위로 분할한다. PYC 파일의 줄 번호 정보는 조작되거나 생략될 수 있으므로 항상 신뢰할 수 없다. 그래서 PYLINGUAL은 BERT 기반 분할 모델을 사용하여 각 바이트코드 명령어가 문장의 시작, 내부, 끝 중 어디에 해당하는지 예측한다.

셋째, 분할된 바이트코드 문장을 Python 소스 코드 문장으로 번역한다. 이 과정은 시퀀스-투-시퀀스 번역 문제로 다루며, CodeT5 계열의 encoder-decoder Transformer 모델을 사용한다. 일반 자연어 토크나이저가 아니라 Python 바이트코드와 소스 코드 구조에 맞춘 커스텀 토크나이저를 사용한다는 점도 특징이다.

넷째, 번역된 문장들을 바탕으로 제어 흐름과 들여쓰기를 복원한다. Python은 들여쓰기가 문법적 의미를 가지므로, 단순히 문장만 복원해서는 올바른 소스 코드가 되지 않는다. PYLINGUAL은 CFG와 CDG를 구성하여 if, while, for, try 같은 제어 구조를 분석하고, 각 문장에 필요한 들여쓰기 수준을 부여한다.

다섯째, 복원된 소스 코드를 다시 컴파일하여 원본 PYC와 비교한다. 이를 통해 디컴파일 결과가 원본과 명령어 수준에서 일치하는지 검증한다. 논문에서는 이 기준을 perfect decompilation이라고 부른다.

## 4. 실험과 결과

논문은 PYLINGUAL의 성능을 평가하기 위해 CSN, PyPI, VirusTotal, PyLingual.io 네 가지 데이터셋을 사용했다. 각 데이터셋은 성격이 다르다. CSN은 비교적 짧고 단순한 공개 코드가 많고, PyPI는 실제 Python 패키지 코드이기 때문에 더 다양하다. VirusTotal은 악성코드 샘플이 포함되어 있어 난독화나 복잡한 제어 흐름이 나타날 수 있으며, PyLingual.io는 실제 사용자가 업로드한 다양한 PYC 파일로 구성된다.

평가 결과 PYLINGUAL은 기존 디컴파일러인 uncompyle6, decompyle3보다 전반적으로 높은 perfect decompilation 비율을 보였다. 특히 기존 도구들이 비교적 잘 지원하던 Python 3.6~3.8 구간에서도 성능 향상이 있었고, Python 3.9~3.12처럼 기존 도구의 지원이 약한 최신 버전에서는 더 큰 차이를 보였다.

논문에 따르면 Python 3.6~3.8에서는 기존 최고 성능 디컴파일러 대비 평균적으로 CSN 13.9%, PyPI 36.2%, PyLingual.io 26.0%, VirusTotal 22.4% 향상되었다. Python 3.9~3.12에서는 CSN 78.0%, PyPI 74.4%, VirusTotal 48.0%, PyLingual.io 43.4% 향상되었다.

### 실제 성공률 비교

| 데이터셋 | Python 버전 | PYLINGUAL | 기존 최고 도구 | 차이 |
|---|---:|---:|---:|---:|
| CSN | 3.6~3.8 | 96.4% | 82.5% | +13.9%p |
| PyPI | 3.6~3.8 | 81.2% | 45.0% | +36.2%p |
| VirusTotal | 3.6~3.8 | 50.2% | 27.7% | +22.4%p |
| PyLingual.io | 3.6~3.8 | 64.1% | 38.1% | +26.0%p |
| CSN | 3.9~3.12 | 95.7% | 17.7% | +78.0%p |
| PyPI | 3.9~3.12 | 82.2% | 7.7% | +74.4%p |
| VirusTotal | 3.9 | 57.5% | 9.5% | +48.0%p |
| PyLingual.io | 3.9~3.12 | 56.7% | 13.3% | +43.4%p |

다만 VirusTotal과 PyLingual.io 같은 실제 환경 데이터셋에서는 성공률이 상대적으로 낮았다. 이는 큰 함수, 깊게 중첩된 예외 처리, 난독화, 다양한 파일 형식 등이 영향을 주기 때문이다. 하지만 이런 어려운 조건에서도 PYLINGUAL은 비교 대상보다 높은 성능을 보였다.

## 5. 논문의 의의

이 논문의 가장 큰 의의는 Python 디컴파일 문제를 기존의 규칙 기반 접근에서 벗어나 데이터 기반 번역 문제와 정적 검증 문제의 결합으로 다루었다는 점이다. 단순히 AI 모델에 모든 것을 맡기는 방식이 아니라, 바이트코드 분할과 문장 번역에는 NLP 모델을 사용하고, 제어 흐름 복원과 결과 검증에는 기계적인 분석을 사용한다. 이 조합은 실용적인 장점이 있다.

또한 perfect decompilation이라는 평가 기준을 사용했다는 점도 중요하다. 복원된 코드를 실제로 실행해 보는 동적 테스트 방식은 입력에 따라 결과가 달라질 수 있고, 악성코드 분석 상황에서는 실행 자체가 위험할 수 있다. 반면 PYLINGUAL은 복원된 코드를 다시 컴파일한 뒤 원본 PYC와 비교하므로, 더 안전하고 재현 가능한 검증이 가능하다.

## 6. 한계와 비판적 검토

PYLINGUAL은 기존 디컴파일러보다 높은 성능을 보였지만, 모든 경우를 완벽히 해결하는 것은 아니다. 특히 실제 악성코드나 난독화된 코드처럼 제어 흐름이 비정상적으로 복잡한 경우에는 여전히 실패할 수 있다. 또한 모델을 Python 버전별로 학습해야 하므로, 새로운 Python 버전이 등장했을 때 학습 데이터와 모델 갱신이 필요하다는 부담도 남아 있다.

perfect decompilation은 엄격한 기준이기 때문에, 원본과 의미상 동등한 코드라도 바이트코드 구조가 다르면 실패로 판정되는 false negative가 발생할 수 있다. 따라서 이 기준은 잘못된 결과를 검증된 것으로 표시할 가능성을 줄이는 대신, 사람이 분석하기에 충분한 결과도 검증 실패로 분류할 수 있다는 한계가 있다.

그럼에도 이 기준은 보안 분석이나 포렌식 환경에서는 장점이 크다. 특히 악성코드 분석에서는 “대충 비슷한 코드”보다 “원본과 일치한다고 검증 가능한 코드”가 더 중요하기 때문이다.

## 7. 느낀 점

이 논문을 읽으면서 Python이 겉으로는 간단하고 편리한 언어처럼 보이지만, 내부적으로는 상당히 복잡한 실행 구조를 가지고 있다는 점을 알 수 있었다. 평소에는 Python의 들여쓰기 문법이 C언어의 세미콜론이나 중괄호보다 편하다고 생각했지만, 디컴파일 관점에서는 들여쓰기와 제어 흐름을 다시 복원해야 하기 때문에 오히려 어려운 요소가 될 수 있다는 점이 인상적이었다.

또한 C언어의 세미콜론과 중괄호는 단순히 불편한 문법이 아니라 문장과 블록의 경계를 명확하게 표시하는 역할을 한다는 것도 알게 되었다. Python은 사람이 읽고 쓰기에는 직관적이지만, 바이트코드에서 다시 원래 소스 구조를 복원할 때는 if, while, for, try 같은 구조를 분석해 들여쓰기까지 재구성해야 한다.

결국 이 논문은 Python 디컴파일이 단순한 코드 복원이 아니라, 언어 설계, 컴파일러 변화, 제어 흐름 분석, 머신러닝 모델이 함께 얽힌 복합적인 문제라는 점을 보여준다. PYLINGUAL은 이러한 문제를 해결하기 위해 NLP 모델과 정적 분석을 결합했다는 점에서 의미 있는 연구라고 볼 수 있다.

### 해석

내가 이 논문에서 가장 설득력 있다고 생각한 부분은 NLP 모델이 생성한 복원 결과를 그대로 신뢰하지 않고, 원본 PYC와의 바이트코드 비교를 통해 검증한다는 점이다. PYLINGUAL은 복원된 Python 코드를 원본과 같은 Python 버전으로 다시 컴파일한 뒤, 원본 PYC와 명령어, 인자, 순서 및 예외 테이블 같은 주요 메타데이터를 비교한다. 두 결과가 일치할 때만 검증된 결과로 표시하고, 일치하지 않으면 검증 실패를 알린다. 이 방식은 모델의 오류 자체를 없애지는 않지만, 잘못된 복원 결과가 검증된 정답처럼 제시되는 위험을 줄인다는 점에서 보안 분석에 적합하다고 생각한다.

## 8. 결론

PYLINGUAL은 변화가 잦은 Python 바이트코드 환경에서 기존 규칙 기반 디컴파일러의 한계를 줄이기 위해 제안된 새로운 디컴파일 프레임워크이다. 이 논문은 바이트코드 분할, 문장 번역, 제어 흐름 복원, perfect decompilation 검증을 결합하여 Python 3.6~3.12까지 폭넓은 버전을 지원하고, 기존 도구보다 높은 정확도를 보였다.

특히 최신 Python 버전에서 기존 디컴파일러들이 약한 모습을 보인 반면, PYLINGUAL은 데이터 기반 접근을 통해 더 나은 확장성을 보여주었다. 아직 난독화된 코드나 복잡한 실제 샘플에서는 한계가 있지만, Python 디컴파일 연구에서 규칙 기반 방식만으로는 부족하다는 점을 잘 보여주는 논문이다.

참고문헌: Wiedemeier et al., “PYLINGUAL: Toward Perfect Decompilation of Evolving High-Level Languages,” IEEE Symposium on Security and Privacy, 2025.
